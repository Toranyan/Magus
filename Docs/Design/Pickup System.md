# Pickup System Design

## Purpose

The Pickup System manages all collectible objects that exist in the game world.

Pickups are physical world objects generated by gameplay systems such as enemy deaths, treasure chests, breakable objects, scripted events, and quest rewards. Once spawned, pickups remain in the world until they are collected, expire, or are otherwise removed.

The Pickup System is responsible for the lifecycle of pickups after they have been spawned.

---

# Goals

* Fully data-driven
* Support all collectible object types
* Object pooling friendly
* Decoupled from the Loot System
* Easy to extend with new pickup types
* Consistent collection behavior
* Support attraction (magnet) effects
* Support multiplayer in the future

---

# Responsibilities

The Pickup System is responsible for:

* Creating pickups from spawn requests
* Initializing pickup data
* World placement
* Spawn animation
* Idle behavior
* Collection detection
* Applying pickup effects
* Playing VFX and SFX
* Returning objects to the pool

The Pickup System is **not** responsible for deciding what should drop. That responsibility belongs to the Loot System.

---

# Architecture

```text
Loot System
      │
      ▼
PickupSpawner
      │
      ▼
Pickup
      │
      ▼
Player Collects
      │
      ▼
Pickup Effect
      │
      ▼
Destroy / Return to Pool
```

---

# Components

## PickupSpawner

Responsible for creating pickups in the world.

### Responsibilities

* Receive PickupSpawnRequests
* Choose spawn position
* Apply spawn spread
* Retrieve objects from pool
* Initialize Pickup component

The PickupSpawner does not determine rewards.

---

## Pickup

Represents a collectible object in the world.

Each Pickup references a PickupData asset describing its behavior.

### Responsibilities

* Store PickupData
* Handle spawn animation
* Detect player collection
* Trigger pickup effects
* Play collection VFX/SFX
* Return itself to the pool

---

## PickupData

ScriptableObject describing a pickup.

Contains all static data required by a Pickup instance.

Example properties:

* Display Name
* Icon
* World Prefab
* Pickup Radius
* Magnet Radius
* Lifetime
* Collection Delay
* Spawn VFX
* Collection VFX
* Spawn SFX
* Collection SFX
* Pickup Effect

Because PickupData is shared, designers can rebalance pickups without changing code.

---

## PickupEffect

Defines what happens when the pickup is collected.

Examples:

* Grant Experience
* Restore Health
* Restore Mana
* Add Currency
* Unlock Ability
* Give Buff
* Grant Key Item
* Trigger Event

Effects should remain independent from the Pickup itself.

A Pickup simply executes its assigned PickupEffect.

---

# Pickup Lifecycle

## 1. Spawn

The PickupSpawner receives a PickupSpawnRequest.

A Pickup object is taken from the object pool.

The Pickup is initialized using its PickupData.

Optional spawn animation begins.

---

## 2. Idle

The Pickup exists in the world.

Possible behaviors include:

* Floating animation
* Rotation
* Bobbing
* Glowing
* Particle effects

Gameplay systems may also interact with the Pickup during this phase.

Examples:

* Magnet attraction
* Vacuum abilities
* Conveyor belts
* Wind effects

---

## 3. Collection

When the player enters the collection radius:

* Validate collection conditions
* Execute PickupEffect
* Play VFX
* Play SFX
* Notify interested systems

---

## 4. Removal

After collection:

* Disable interactions
* Stop visual effects
* Return object to pool

If the Pickup expires before collection:

* Play expiration effect (optional)
* Return object to pool

---

# Spawn Request

The Pickup System receives requests from external systems.

```text
PickupSpawnRequest

PickupData Pickup

int Quantity

Vector3 Position
```

A single request may generate multiple Pickup instances depending on quantity.

---

# Collection Flow

```text
Player Enters Collection Radius
            │
            ▼
Pickup Valid?
            │
            ▼
Execute PickupEffect
            │
            ▼
Play VFX/SFX
            │
            ▼
Notify Systems
            │
            ▼
Return Pickup to Pool
```

---

# Interaction Rules

A Pickup may support additional gameplay rules.

Examples include:

* Collection delay after spawning
* Owner-only collection period
* Team restrictions
* Distance requirements
* Auto-collection
* Manual interaction
* Quest requirements

These rules should remain configurable through PickupData where possible.

---

# Separation of Responsibilities

**Loot System**

Determines what rewards should be generated.

**PickupSpawner**

Creates pickups in the world.

**Pickup**

Represents a collectible object.

**PickupEffect**

Applies gameplay effects after collection.

This separation keeps reward generation independent from world interaction.

---

# Future Extensions

Potential future features include:

* Magnet upgrades
* Pickup rarity visuals
* Stack merging
* Shared loot
* Personal loot
* Multiplayer ownership
* Network prediction
* Pickup chaining
* Auto-loot pets
* Inventory pickups
* Physics-based pickups
* Environmental interactions
* Scriptable pickup behaviors
* Conditional collection requirements

The architecture supports these additions without requiring changes to the core Pickup lifecycle.
